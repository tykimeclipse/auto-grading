# 대단원별 누적 성취도 3단계 화면 체크리스트

## 구현 대상

1. `frontend/major-unit-achievement.css`
2. `frontend/major-unit-achievement-ui.js`
3. `frontend/student-achievement-v2.html`
4. `frontend/student-management.html`
5. `db/course_enrollment_achievement_stage7_part3_history_event_date_timezone.sql`
6. `db/audit_course_enrollment_achievement_stage7_part3_history_event_date_timezone.sql`

학생 공개 성취도와 교사 학생관리 화면은 같은 공통 렌더러·보기 컨트롤러와
표 구조를 사용한다. 화면별 코드는 RPC 요청과 문구 차이만 담당한다.
공통 JavaScript 참조는 현재 `?v=2`로 캐시를 갱신한다. 이후 파일을 수정할
때에도 두 HTML의 버전 값을 함께 올린다.

## 선행 조건

- `db/audit_course_enrollment_achievement_stage7_part2_major_unit_achievement.sql`의 다섯 섹션이 모두 `blocking_issue_count = 0`이어야 한다.
- HTML 배포 전에 공통 CSS와 JavaScript 파일을 함께 배포해야 한다.
- 날짜 보정 SQL은 기존 시험 기록의 `event_date` 계산만 `Asia/Seoul` 기준으로
  고정한다. 반환 구조·점수 산식·정렬·데이터는 변경하지 않는다.
- 과거 stage6 Part 2A 원본은 Part 2B 이전 구·신 등가 감사를 재현할 수 있도록
  당시의 세션 시간대 기준을 유지한다. 현재 운영 함수의 날짜 교정은 신규
  stage7 Part 3 SQL로 배포한다.
- stage7 Part 3 적용 후 stage6 Part 2A를 재실행하면 날짜 교정이 되돌아간다.
  이 경우 아래 배포 순서의 1~3번을 연속으로 다시 실행해야 한다.

## 배포 순서

1. 함수 소유자 권한의 Supabase SQL Editor에서
   `course_enrollment_achievement_stage7_part3_history_event_date_timezone.sql`을 실행한다.
2. `audit_course_enrollment_achievement_stage7_part3_history_event_date_timezone.sql`을
   실행하고 두 차단 섹션이 모두 `0`인지 확인한다.
3. `audit_course_enrollment_achievement_stage6_part2b_postcutover.sql`을 다시 실행해
   기존 전체 조회 래퍼와 공통 코어의 등가성을 확인한다.
4. 공통 CSS·JavaScript를 먼저 배포하고 두 HTML을 함께 배포한다.
5. 브라우저 캐시 영향을 피하기 위해 `Ctrl+F5`로 새로고침한다.

> 재실행 규칙: stage6 Part 2A를 나중에 다시 실행한 경우에도 1~3번을 생략하지
> 않는다. Part 3 구현 SQL을 다시 적용한 뒤 날짜 감사와 Part 2B 컷오버 감사를
> 모두 통과해야 현재 운영 정의가 복구된 것으로 본다.

## 화면 계약

- 기본 보기는 기존 `시험 기록`이다.
- `단원별 성취도`를 처음 누를 때 현재 조회 범위로 신규 RPC를 호출한다.
- 조회 범위는 기존과 동일한 `전체 누적 / 강좌 / 강좌 미지정 과거 기록`을 사용한다.
- 요약 행은 `단원 / 완료 평가 / 1차 / 2차 반영 / 최종 / 학습 유지`를 표시한다.
- 점수는 테스트별 백분율 평균이 아니라 RPC가 계산한 문항 수 가중 평균을 표시한다.
- 완료·검토 필요 attempt만 집계하므로 건수 라벨은 `시험 기록`이 아니라 `완료 평가`로 표시한다.
- 단원 행을 누르면 테스트별 `평가일 / 시험명 / 문항수 / 1차 / 2차 반영 / 최종`을 펼친다.
- 테스트 상세는 단원별 최근 200건을 선택한 뒤 오래된 평가부터 표시한다.
- 상세이 200건을 초과하면 전체 건수와 반환 건수를 안내한다.
- 200건 상한으로 상세이 잘린 단원은 반환 배열의 첫 행을 전체 이력의
  `첫 평가`로 표시하지 않는다. 마지막 행의 `최근 평가` 표시는 유지한다.
- 단원 정렬은 학년 순서와 교육과정·과목·대단원 코드를 사용하며, 중등·고등은 `M1 → M2 → M3 → H1 → H2 → H3` 순서를 보장한다.
- 메타데이터가 없는 기존 평가는 마지막 `단원 미지정` 행으로 표시한다.
- 학습 유지는 최종 확정 반복 평가를 우선하고, 최종 비교 표본이 부족하면 1차 반복 평가를 보조 기준으로 사용한다.
- 반복 평가가 두 건 이상이면 최근 점수, 직전 대비 변화, 마지막 평가 후 경과일을 표시한다.

## 학생 공개 화면 확인

1. 유효한 공개 링크로 접속하면 기존 누적 카드와 시험 기록이 이전과 동일하게 표시된다.
2. `단원별 성취도`를 누르면 현재 선택한 강좌 범위의 단원만 표시된다.
3. `전체 누적`, 운영 중 강좌, 종료 강좌, 강좌 미지정 범위를 차례로 변경해 단원 데이터가 함께 갱신되는지 확인한다.
4. 단원 행을 열고 닫을 수 있으며 시험 상세가 오래된 순서인지 확인한다.
5. 수동 시험은 `단일 평가`로 표시되고 2차 반영 값이 `-`인지 확인한다.
6. 유효하지 않거나 만료된 공개 링크는 학생 또는 단원 데이터를 노출하지 않는지 확인한다.
7. 같은 시험의 평가일이 시험 기록과 단원별 상세에서 동일한지 확인한다.

## 교사 학생관리 화면 확인

1. 학생을 선택한 뒤 기존 누적 카드와 시험 기록이 이전과 동일하게 표시된다.
2. `단원별 성취도`를 누르면 학생코드 RPC 결과가 표에 표시된다.
3. 단원 행의 수치와 공개 학생 화면의 동일 학생·동일 범위 수치가 일치하는지 확인한다.
4. 수동 시험은 `수동` 배지로 표시되는지 확인한다.
5. 학생을 빠르게 연속 선택하거나 강좌 범위를 빠르게 변경해도 이전 요청 결과가 새 학생·새 범위에 덮어써지지 않는지 확인한다.
6. 학생 메타정보 수정과 수강 강좌 관리 기능이 기존대로 동작하는지 확인한다.
7. 휴원 또는 비활성 학생은 상세 화면을 유지하면서 성취도 조회 제한을
   이해할 수 있는 한국어 안내로 표시하는지 확인한다.

## 반응형·접근성 확인

1. 데스크톱과 모바일 너비에서 요약표와 상세표가 가로 스크롤로 잘리지 않고 조회되는지 확인한다.
2. 키보드로 보기 전환 버튼과 단원 펼치기 버튼을 조작할 수 있는지 확인한다.
3. 현재 보기 버튼의 강조와 `aria-pressed` 값이 함께 변경되는지 확인한다.
4. 점수가 없는 단계는 `-`로 표시되고 `null%`, `NaN%`가 노출되지 않는지 확인한다.
